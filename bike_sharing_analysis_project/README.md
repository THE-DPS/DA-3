# Bike-Sharing Demand Analysis and Prediction

A reproducible six-stage internship project using the UCI Bike Sharing dataset.

## Scope
Analyze historical daily rental demand and compare a baseline, Linear Regression, and Random Forest model. The source data cover Washington, D.C. in 2011–2012; this is not a live/current forecasting service.

## Dataset and attribution
- Source: UCI Machine Learning Repository — Bike Sharing
- DOI: https://doi.org/10.24432/C5W894
- Dataset page: https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset
- License: CC BY 4.0 as listed by UCI
- File used: `day.csv` (daily aggregation). Do not combine it with `hour.csv`, as they represent overlapping activity at different aggregation levels.

## Setup
Python 3.10+ recommended.

```bash
python -m venv .venv
# macOS/Linux
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
python src/download_data.py
python src/prepare_data.py
python src/run_eda.py
python src/train_model.py
streamlit run app.py
```

The downloader retrieves the official UCI archive. An internet connection is required for the first download. If you already downloaded the UCI archive, place `day.csv` in `data/raw/`.

## Outputs
Generated artifacts are written under `outputs/`: profiling JSON, cleaned data, EDA figures, model metrics, predictions, and residual diagnostics. These are generated by execution; the repository does not hard-code fabricated model scores.

## Modeling safeguards
- `cnt` is the target.
- `casual` and `registered` are excluded because they sum to `cnt` and would leak target information.
- `instant` is excluded as an index.
- Data are sorted by date and split chronologically; the latest observations form the test set.
- Hyperparameter selection uses training data only.
- Metrics are MAE, RMSE, and R². Results should be reported with the test period and limitations.

## Important limitations
This is a historical, single-city dataset. Findings do not establish causality and should not be generalized to present-day systems without external validation. Weather fields are normalized in the source data.

## Folder structure
- `src/download_data.py`: fetch and extract the official dataset
- `src/prepare_data.py`: validate, profile, and clean daily data
- `src/run_eda.py`: generate descriptive statistics and figures
- `src/train_model.py`: train, tune, and evaluate models
- `app.py`: interactive Streamlit dashboard
- `Weekly_Reports/`: six separate Word reports
